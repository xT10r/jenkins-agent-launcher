# Спецификация текущей версии

## Назначение

`Jenkins Agent Launcher` - Windows-приложение на Python/PyQt5, которое запускает `agent.jar`, показывает статус в GUI и пишет лог работы агента.

## Поддерживаемые режимы

| Режим | Как включается | Что происходит |
|------|-----------------|----------------|
| GUI | по умолчанию | Открывается окно, создаётся tray-иконка, агент запускается в фоне |
| Console | `--no-gui` | GUI не создаётся, статусы печатаются в консоль, лог пишется в файл |
| Test config | `--test-config` | Конфигурация валидируется, после чего приложение завершается |

## Источники конфигурации

Фактический приоритет в `src/config.py`:

1. значения по умолчанию;
2. `config/config.json`;
3. `config.json` в корне для legacy-совместимости;
4. аргументы CLI;
5. переменные окружения `JENKINS_*`.

Если runtime-конфиг отсутствует, launcher может создать `config/config.json` из `config/config.template.json`.

## Конфигурация

Обязательные поля:

- `agent.jenkinsUrl`
- `agent.agentName`
- `agent.secret`, кроме режима `jnlp.enabled=true`, где secret может быть получен из JNLP перед запуском агента

Поддерживаемые секции:

- `agent`
- `logging`
- `download`
- `jnlp`
- `fallback`
- `behavior`
- `update`
- `environment`
- `ui`

Текущая реализация:

- `download.timeout` и `download.chunkSize` применяются в `src/downloader.py`;
- `jnlp.enabled` разрешает получить `agent.secret` из JNLP, `jnlp.refreshSecret` принудительно обновляет его перед запуском, `jnlp.saveSecret` записывает полученное значение в runtime `config.json`;
- `agent.logFileName` и `--log-path` задают базовый путь лог-файла, поверх которого работает ротация;
- `agent.java_opts` добавляется в команду запуска Java перед `-jar`.
- `agent.javaHome` и `--java-home` позволяют явно указать корень JDK/JRE или путь к `java(.exe)`.
- `agent.tempDir` и `--temp-dir` задают временный каталог launcher/Java; путь может быть относительным или абсолютным, Java получает `-Djava.io.tmpdir=<path>`.

## Фильтрация ENV

Секция `environment.ignoredVars` задаёт список переменных окружения, которые launcher удалит перед запуском `java`.

Поддерживаются два формата элементов:

- строка, например `"JENKINS_SECRET"`;
- объект вида `{ "name": "JENKINS_SECRET", "reason": "..." }`.

Если переменная реально присутствует в окружении launcher, причина её исключения дополнительно пишется в лог при старте приложения.

## Политика TLS для agent.jar

Основной URL Jenkins и fallback URL теперь управляются явными флагами `verifySsl`.

- `agent.verifySsl`
  Значение по умолчанию вычисляется автоматически:
  для `https://...` используется `true`, для незащищённых адресов `http://...` используется `false`.
- `fallback.verifySsl`
  По умолчанию `true`. Отключать стоит только осознанно и на свой риск.

Launcher больше не должен молча переключаться в небезопасный режим проверки сертификата без явной настройки.

## GUI

Реально реализовано:

- окно со статусом, PID и live-логом;
- кнопки `Запуск`, `Перезапуск`, `Остановить`;
- меню `Файл`, `Вид`, `Справка`;
- tray-иконка с показом окна, логом, перезапуском, остановкой и выходом;
- переключение светлой/тёмной темы;
- настройка `ui.startMinimized`, управляющая стартом в свёрнутом виде.

Ограничение:

- `MainWindow` не обновляет `_proc_running`, поэтому доступность кнопок и пунктов меню не соответствует фактическому состоянию агента.

## Запуск агента

`src/agent_controller.py` выполняет:

1. HEAD-запрос к `JenkinsUrl/api/json`;
2. попытку `attach` к уже живому подходящему Java-процессу Jenkins-agent;
3. загрузку `agent.jar`, только если attach не состоялся и включено `autoUpdateJar` или файла ещё нет;
4. поиск Java в порядке: `agent.javaHome` / `--java-home` → `PATH` → `JAVA_HOME`;
5. запуск `java -jar agent.jar ...`, если attach не состоялся;
6. мониторинг процесса и перезапуск по политике `maxRestarts`.

Для корректно подхваченного Java-процесса пользовательские `Остановить` и `Перезапуск` теперь допустимы:

- `stop` завершает attach-процесс через OS-level terminate path;
- `restart` завершает attach-процесс и запускает новый цикл уже под управлением launcher;
- при этом attach по-прежнему не происходит для неоднозначных кандидатов.

## Безопасность

Реально реализовано:

- переменные `JENKINS_*` не пробрасываются в дочерний Java-процесс;
- секрет передаётся через временный файл;
- временный файл секрета затирается нулями перед удалением.

Ограничения:

- `src/ssl_check.py` присутствует, но не используется в основном сценарии запуска;
- после любой ошибки загрузки код всегда пытается перейти в режим `verify=False`, а не только после SSL-ошибок;
- fallback URL тоже скачивается с `verify=False`.
